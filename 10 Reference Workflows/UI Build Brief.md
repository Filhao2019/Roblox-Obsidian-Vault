# UI Build Brief

A reusable brief for one usable screen or HUD. This is an original planning tool; no runnable system or tested Studio implementation is supplied by this note.

## Prepare the references

Choose examples for information hierarchy, layout and motion separately. List the data the player must read first, actions they must reach and which reference details you will replace with original artwork.

Example task: a hotel supply shop with a category list, item details and a purchase action. Specify loading, empty, unavailable, unaffordable, pending, success and failure states that apply to the project.

## Ask for a concrete deliverable

An Explorer hierarchy, responsibilities for client UI and authoritative game logic, sizing and anchor choices, focus order, touch controls, state transitions, cleanup behavior and an implementation in the project's existing UI approach. Confirm current Roblox APIs from the relevant official docs before writing code.

## Copyable task frame

```text
Build the feature described below in the existing Roblox project.
Outcome:
Inspected reference files or URLs, with each one's role:
Observed patterns to adapt:
Original design choices:
Target devices, input methods and rig:
Existing project structure and tool access:
Measured constraints and unresolved decisions:
Required interactions and failure states:
Deliverables and asset locations:
Acceptance checks:

Inspect the selected references before drawing visual conclusions.
Implement within the available project tools and report exact changed files.
Distinguish static review, executed tests and checks still pending.
```

## Acceptance review

Open, close and reopen the screen; resize it; test a long item name, a large currency value, rapid actions and a failed request. Verify the intended input methods. Record screenshots and actual test results, including any device checks not run.
