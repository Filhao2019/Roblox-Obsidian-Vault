# VFX and Audio Brief

A reusable brief for one synchronized gameplay cue. This is an original planning tool; no runnable system or tested Studio implementation is supplied by this note.

## Prepare the references

Choose references for the visible silhouette and phase structure; use playable, appropriately sourced audio for sound decisions. Record anticipation, event, decay and what feedback must remain readable. The external sfx collection contains visual references, not an audio library.

Example task: an interactable service bell with a short response cue. Keep the cue restrained enough to preserve speech, navigation and other important signals.

## Ask for a concrete deliverable

An event timeline, effect hierarchy, sound-source location, lifecycle and cleanup rules, concurrency behavior and any accessibility settings the project supports. Separate a gameplay event from cosmetic presentation and identify which side of the network owns each responsibility.

## Copyable task frame

```text
Build the feature described below in the existing Roblox project.
Outcome:

Deliverables and asset locations:
Acceptance checks:

Inspect the selected references before drawing visual conclusions.
Implement within the available project tools and report exact changed files.
Distinguish static review, executed tests and checks still pending.
```

## Acceptance review

Test repeated triggers, overlapping effects, moving away from the source and interruption. Inspect visibility against bright and dark backgrounds; listen to the actual mix. Record measured performance and loudness decisions rather than inventing universal limits.
