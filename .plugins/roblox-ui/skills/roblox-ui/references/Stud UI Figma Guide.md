# Stud UI Figma Guide

Agent-ready brief for the tactile stud-style HUD: a layered base button (gradient face, 5–8 px dark extrusion, clipped stud texture, outlined label), the Shop/Rebirth/Index/Settings colour set, a green currency counter with a plus button and a wide toggle, then the Studio translation and acceptance checklist. Pair it with [[Cartoony UI Figma Guide]] for menu windows and [[Figma Workflow for Roblox UI]] for the handoff.

> Imported from the user's session brief folder on 2026-11-19. Based on the video's chapter summary and transcript, not a frame-by-frame audit. Values marked suggested are defaults, not measurements.

**Reference:** [The Greatest Stud UI Tutorial on Roblox (w/ Figma)](https://www.youtube.com/watch?v=gnIKtS3nUqo)

**Purpose:** Instruct an AI design/coding agent to reproduce the visual language and component construction of the tutorial's bright, tactile, cartoony Roblox stud-style interface. This is a production brief, not a claim that every pixel value is specified by the video. Values marked *suggested* are implementation defaults; adjust them against actual video frames/screenshots.

## 1. Overall art direction

Build a colorful, playful, chunky Roblox game HUD that looks like a collection of polished plastic toy buttons. The interface must not look like a flat modern SaaS dashboard. Its defining visual characteristics are rounded or softened geometric shapes, stacked faces and darker offset bases that imply thickness, bright directional gradients, strong but controlled outlines, inset or overlaid decorative texture, bold legible outlined text, crisp hard-edged shadows, and colorful category-specific controls. Every interactive element should feel substantial and pressable. The reference tutorial constructs these shapes in Figma using multiple layers rather than relying on a single plain rectangle. The result is a coherent family of reusable buttons, not a set of unrelated icons. Prioritize clarity at Roblox gameplay scale: visual hierarchy, strong contrast, and enough breathing room for labels.

## 2. Button anatomy: the most important reusable component

Each primary button should be assembled from a layered component. First create a main front shape with rounded corners or a softly squared silhouette; add a vertical or subtly diagonal gradient, typically lighter at the top and deeper at the bottom. Next add a darker backing shape below and offset downward several pixels to create a raised, three-dimensional plastic edge. Apply a bright colored stroke around the front shape and optionally a separate outline around the outer silhouette. Use an interior masked texture layer to place a repeated stud pattern or other small highlights *inside* the front face; the mask must clip the texture at the border. Keep a decorative highlight overlay subtle enough that it does not compete with text. The reference explicitly adjusts masks, texture placement, outlines, and back layers after resizing, so resizing must not distort or misalign the texture. The front face, backing, texture mask, icon, and text must remain separately editable in Figma and, where feasible, as separate Roblox GUI elements.

Recommended starting values for a desktop reference canvas (not measured from the video): 3–5 px visual outlines, 5–8 px downward extrusion, 8–16 px corner radii, and a small controlled top highlight. Scale these as a *system* rather than increasing some outlines independently. When the tutorial scales a button, it later corrects stroke thickness; reproduce this discipline. Avoid huge blurry shadows: the tutorial repeatedly favors shadows with blur set to zero and high opacity, making the interface feel crisp and cartoon-like. Use darker colors for extrusion rather than plain black wherever possible.

## 3. Typography and labels

Use a bold, friendly, highly legible display font with a cartoony Roblox aesthetic. Set button labels in white or another very light color, with a dark or chromatically coordinated outline and a tiny hard-offset shadow for depth. The reference explicitly tunes text strokes and drop-shadow offsets, sometimes reducing them from approximately 3 px to 2 px when they become visually overpowering. Text should be centered optically, not merely mathematically, and should never touch the edges of the button. In the tutorial, the creator later reduces the left-side menu labels to around 25 px to keep long words such as “Settings” comfortably inside their buttons. Preserve consistent baseline, outline weight, and text hierarchy across repeated components. Avoid excessively condensed type, tiny captions, or unoutlined text on bright gradients.

## 4. Stud pattern, masks, and decorative overlays

A central identifying feature is the stud-inspired texture. Use a repeating raised-dot/stud graphic or carefully designed decorative pattern that evokes Roblox toy-like surfaces. Put it in a clipped group mask so it cannot extend beyond the button. The tutorial manually resizes and repositions the stud texture when changing the dimensions of the component. It also uses a sunburst image in the shop button, resized inside the mask and set to an **Overlay** blend mode. Keep this kind of effect secondary and low-opacity; its job is to add depth, not to obscure icons or text. Decorative assets must be high-resolution, crisp, and stylistically unified. Avoid unrelated photo textures, noisy gradients, or unlicensed third-party graphics.

## 5. Top action/teleport buttons

Create a row or group of matching primary buttons across the upper portion of the HUD. The tutorial finishes these top buttons and groups them under a name such as **Toggle Buttons** or **Teleport Buttons**; it also renames a base control **Sell Button**. Reuse the same layered construction for each button: consistent front-face dimensions, backing depth, texture treatment, strokes, label styling, and spacing. Only change each button's semantic color, icon, and text. If a top control toggles a state, make the on/off difference visible without breaking the visual system. Keep the top group aligned and ensure it does not collide with other game HUD elements or Roblox top-bar insets.

## 6. Left-side menu: four distinct colored actions

Create a vertically arranged group of four prominent controls: **Shop**, **Rebirth**, **Index**, and **Settings**. The video duplicates a common base button, reshapes it toward a roughly 70×70 square starting point, then increases the size when it looks too small. This 70×70 measurement is a stage of construction, not a universal final size. Each button should feature an icon above or behind its text, with the icon nested inside the button group for correct alignment. Use the following color language based on the tutorial: Shop uses a vibrant blue gradient with a darker blue base and a blue-tinted outline; Rebirth uses a pink/purple gradient and dark purple extrusion; Index uses a lively green gradient and dark green base; Settings uses a light gray-to-near-white face, a bright outline, and darker gray backing. Maintain the same silhouette and 3D effect across all four. The reference resizes the left/right edges and adjusts inner strokes so the proportions feel balanced. Long labels must be slightly reduced to preserve horizontal padding. The creator groups all these controls as **Left Side Buttons** and uses alignment tools to center the group vertically. Replicate the grouping and vertical rhythm; don't manually place each item at arbitrary offsets.

## 7. Icon composition and visual hierarchy

Use clear, playful icons whose silhouette is recognizable at small size. Icons should be large enough to identify instantly but should not overpower the label. Put each icon inside the correct button group and keep it behind the text when that improves legibility. The video explicitly moves an icon below the text in the layer stack and notes that the arrangement can still look good. For Shop, a shop/store symbol is appropriate; for Rebirth, a circular arrow or renewal symbol; for Index, a book, catalog, or collection symbol; for Settings, a gear. These icon choices are implementation suggestions except for the general functions demonstrated. Prefer a consistent outline style and comparable visual weight. If the icon already includes a border, avoid adding a second thick outline that makes it muddy.

## 8. Bottom currency display and purchase control

Add a cash balance near the bottom edge of the HUD. The tutorial demonstrates a bright green money string beginning with a dollar sign, adjusts its size to approximately **46 px** during construction, then reduces the displayed number of digits because it takes up too much space. Use a large bold green font with a dark outside stroke, rounded stroke joins, and a hard-edged shadow. The creator experiments with outline weights around 3–5 px and settles on a restrained result. The number must be dynamic, formatted with separators, and tested for large values. Place a small green **+** button immediately to its right, built as its own two-layer raised button with a lighter top face, darker green bottom, bright inner stroke, and white plus symbol. The video constructs the plus control from square shapes and uses a tiny hard shadow and reduced stroke weight to keep it readable. Group the currency label and plus button as one bottom HUD cluster; the plus button should open a currency purchase or acquisition panel, not be a decorative glyph.

## 9. Slow Mode control

Reuse the green Index button as a starting point for a wider **Slow Mode On** control. Remove the old icon and remove the sunburst decoration when it no longer fits. Resize the front shape, mask, backing, and stud texture together; the tutorial stretches the texture across a wider horizontal button and adjusts the backing so the extrusion remains about seven pixels in its demonstrated comparison. Center the text and make the status clear. Implement an actual toggle with an alternate **Slow Mode Off** state, including a visually distinct inactive treatment and accessible feedback. Keep the same outline, shadow, and extrusion rules as the rest of the HUD. The reference positions and groups this control near the left-side interface, so coordinate it with the menu rather than allowing overlap.

## 10. Figma workflow and editable layer organization

Start with a consistent reference frame and create one **Base Button** component before making variations. Inside that component, use explicitly named layers such as `Front Face`, `Back Extrusion`, `Outer Stroke`, `Stud Texture Mask`, `Stud Texture`, `Highlight`, `Icon`, `Label`, and `Label Shadow`. Group related pieces with Ctrl+G and rename them clearly. The tutorial repeatedly uses Ctrl-click to select nested layers, Shift-click to select contiguous layer ranges, Alt-drag to duplicate or resize, Ctrl+C/Ctrl+V to copy fills or gradients, and the alignment tools to center content. Treat these actions as examples of efficient Figma editing, not mandatory keystrokes for an automated agent. When cloning a component, change colors and labels without rebuilding geometry. Keep master component variants for top controls, square menu controls, small plus buttons, and wide toggles. Use masks for texture and preserve icon/text stacking order. Make sure every group is individually editable and inspect it after scaling.

## 11. Roblox Studio implementation strategy

Convert the Figma design into a responsive Roblox `ScreenGui`. Use `Frame`, `TextLabel`, `TextButton`, `ImageLabel`, and `ImageButton` as appropriate, with `UICorner` for rounded shapes, `UIStroke` for outlines, `UIGradient` for front-face color gradients, `UIPadding` for label safety, and `UIListLayout` or layout containers for consistent group spacing. Use image assets for complex stud textures, decorative highlights, and any shapes that cannot be represented faithfully by native UI. Use a nine-slice strategy where a textured button must scale without stretching corners or studs. For a raised button, place a darker backing Frame or ImageLabel slightly below the clickable front face. Prefer a separate decorative texture layer with clipping (`ClipsDescendants` on the appropriate container) and test transparency. Use `AnchorPoint`, relative `UDim2` positioning, and constraints so the left-side menu stays aligned and the currency cluster stays at the bottom across screen sizes. Respect `GuiInset`/safe areas and touch targets. Don't assume a fixed 1920×1080 viewport.

Build reusable components or factory functions rather than duplicating ad hoc code. Define a theme object containing colors, stroke widths, corner radii, extrusion offsets, typography sizes, and animation durations. Build variants for `Shop`, `Rebirth`, `Index`, `Settings`, `Sell`, `SlowMode`, and `CurrencyPlus`. Bind button interactions to real game actions, with server-side validation for purchases, rebirth, selling, and currency changes. Do not trust a client-only money value for authoritative transactions. Make sure icons and decorative layers do not intercept clicks. Use named GUI hierarchy elements and clear script ownership. If using external texture files, keep source artwork and exported PNGs organized with meaningful names.

## 12. Motion, hover, and click feedback (implementation enhancement)

The tutorial concentrates on static Figma construction; the following animation guidance is a recommended implementation enhancement rather than a verified on-screen tutorial sequence. On hover, slightly brighten the gradient or enlarge the button by roughly 2–4% while preserving layout. On press, shift the front face down toward its dark backing by a few pixels, reducing the visible extrusion to simulate a physical button being depressed. On release, spring back quickly with a subtle ease-out. Use Roblox `TweenService`, short durations (roughly 0.08–0.18 seconds), and avoid excessive bounce. For mobile, implement press feedback without relying on hover. A toggle should visibly communicate its state, and disabled buttons should have a lower-contrast treatment without losing label readability. Keep effects lightweight so the HUD remains responsive.

## 13. Layout, responsive behavior, and accessibility

The HUD should preserve the following hierarchy: top action buttons; left-side Shop/Rebirth/Index/Settings group; bottom currency and plus control; and the Slow Mode toggle near the left-side region. Use clear separation from the central gameplay view. At 16:9 desktop scale, all elements should feel substantial but should not cover too much of the game world. At narrower or mobile aspect ratios, reduce spacing and overall component scale consistently; if necessary, rearrange top controls or provide a compact menu. Avoid text clipping, overlapping icons, and inaccessible touch targets. Test light and dark game environments because bright text and dark strokes must remain legible over both. Ensure that any state information conveyed by color also has a text or icon cue.

## 14. Quality control and visual acceptance checklist

The result is acceptable only when the buttons read as tactile, raised, cartoony objects rather than flat rectangles; all color variants share the same component anatomy; stud textures stay within masks; front faces and dark backing layers align precisely; outlines and text shadows have consistent visual weight; Shop is blue, Rebirth pink/purple, Index green, Settings pale gray/white; the four left controls form a neatly spaced vertically centered group; the bottom money display is bold green with a working plus button; the Slow Mode control is a wide, correctly textured toggle; and no text touches the button edges. Compare screenshots from the actual tutorial at the same canvas size and adjust colors, spacing, and proportions to match. Do not fabricate exact colors, positions, or icons that are not clearly observable. Validate in Roblox Studio at desktop and mobile resolutions, with mouse, keyboard, and touch input. The deliverable should include reusable GUI components, organized assets, and a demonstration scene showing every button in normal, hovered/pressed, and toggled states.

## 15. Agent execution prompt

**Task:** Recreate the polished Roblox stud-style HUD from the reference tutorial using Figma for editable design and Roblox Studio for functional implementation. First inspect the reference video and capture representative screenshots of the finished HUD and of close-up button construction. Extract a component inventory and infer shared visual tokens; explicitly mark any dimensions or colors that cannot be measured. Build a reusable multi-layer button master with a bright gradient front, dark offset extrusion, coordinated outlines, clipped stud texture, subtle highlight, bold outlined label, and icon slot. Then build the top action/teleport group, the left Shop/Rebirth/Index/Settings group, the bottom green currency counter with plus control, and the wide Slow Mode toggle. Match the tutorial's playful plastic/toy appearance and its color-specific variants. Keep all Figma layers editable and clearly named; translate the design into responsive, maintainable Roblox GUI components. Wire functional states and input feedback, use server-authoritative gameplay actions, and test across viewport sizes. Iterate against screenshots until silhouette, spacing, text treatment, mask alignment, and perceived 3D depth are consistent. Do not replace the reference's layered cartoon aesthetic with flat generic UI. Return the source design, exported textures, Roblox UI hierarchy/scripts, and screenshots of the finished result.
